# context-handoff（上下文交接器）

把整段对话记录 / 工具调用记录浓缩成要点摘要，用于超上下文时交接给新会话。

## 它解决什么问题

当对话或工具返回内容过长、接近上下文上限时，用一个轻量模型把整段历史压成
「要点摘要」，保留关键信息、丢弃过程性废话。摘要生成成功后，以它为种子开一个
新会话，旧原始历史丢弃——相当于把上下文「交接」给下一个干净的上下文窗口。

## 目录结构

- `SUBAGENT.md` —— 子代理定义（frontmatter + 行为指令）
- `README.md` —— 本说明

## 快速理解 `SUBAGENT.md`

| 字段 | 含义 |
| --- | --- |
| `id` | 子代理唯一标识：`context-handoff` |
| `name` | 显示名：上下文交接器 |
| `description` | 一句话用途（供上层调度时匹配） |
| `model` | 实际生成交接摘要的模型：`deepseek-v4-flash` |
| `tools` | 允许的工具（此处为空，纯文本摘要任务） |
| `maxIterations` | 最大迭代次数：`1` |

## 交接摘要规则

1. **必须保留**
   - 用户目标
   - 已完成的步骤
   - 当前任务的确定状态与关键结论
   - 尚未解决的问题

2. **必须丢弃**
   - 过程性废话
   - 重复内容
   - 无信息的工具返回
   - 被后续覆盖的旧状态

3. **输出格式**：只输出纯文本摘要，不要 Markdown 标题，不要解释做法。

## 使用方式

由上层 Agent 在上下文接近上限时，把「对话 + 工具记录」作为输入交给本子代理。
摘要生成成功后，上层丢弃旧原始历史、开启新会话，并以返回的摘要作为新会话的种子，
继续后续推理。
